Propósito general de la asignatura

Evaluar los modelos de desarrollo de software, a través del uso de metodologías ágiles (Scrum/Kanban) gestionadas en jira, con miras a planificar entregas incrementales y medir la productividad del equipo.

Cómo está organizado el curso

El curso avanza como un proyecto real de software: primero se organiza el equipo y su forma de trabajar, después se define qué hay que construir, luego se diseña cómo se va a construir y, finalmente, se colabora para construirlo y darle mantenimiento en equipo.

Unidad 1 — Metodologías Ágiles y Gestión con jira +

Organizar el ciclo de vida del desarrollo mediante la configuración de roles, ceremonias Scrum y tableros Kanban en jira, para asegurar una planificación de entregas iterativas que aporten valor continuo.

  • 1.1 Manifiesto Ágil y mentalidad (Mindset).
  • 1.2 Roles y ceremonias en Scrum: Sprint Planning y Daily.
  • 1.3 Gestión de tareas en jira: estados, prioridades y fechas límite.
  • 1.4 Métricas de agilidad: diagramas de Burndown y velocidad del equipo.
Producto de aprendizaje Documento estructurado de jira con roles definidos y backlog de producto inicial estructurado.
Unidad 2 — Ingeniería de Requerimientos y Documentación +

Estructurar las necesidades del negocio mediante el levantamiento de historias de usuario, criterios de aceptación y priorización MoSCoW, con el fin de definir un alcance técnico ejecutable y sin ambigüedades.

  • 2.1 Técnicas de recolección: entrevistas y observación directa.
  • 2.2 Requisitos funcionales vs. no funcionales (atributos de calidad).
  • 2.3 Redacción de historias de usuario y backlog del producto.
  • 2.4 Negociación y priorización de requerimientos (método MoSCoW).
Producto de aprendizaje Documentación de requisitos conteniendo historias de usuario validadas y matriz de priorización MoSCoW.
Unidad 3 — Modelado Estructural y de Comportamiento (UML) +

Esquematizar la arquitectura lógica y el flujo de procesos del sistema mediante diagramas de clases, secuencia y casos de uso (UML), para estandarizar la comunicación técnica y prever interacciones antes de la construcción.

  • 3.1 Diagrama de casos de uso: actores y límites del sistema.
  • 3.2 Diagrama de clases: atributos, métodos y relaciones (asociación, herencia).
  • 3.3 Diagrama de secuencia: flujo de mensajes entre objetos.
  • 3.4 Diagrama de actividades: modelado de procesos de negocio.
Producto de aprendizaje Portafolio de diagramas UML representando la arquitectura estática y dinámica de la solución de software.
Unidad 4 — Flujos de Trabajo Colaborativos con Git y GitHub +

Sincronizar la evolución del código fuente empleando comandos de Git y estrategias de ramificación profesional, fomentando una cultura de revisión ética y resolución de conflictos para mantener la integridad del proyecto grupal.

  • 4.1 Configuración de Git: init, add, commit y log.
  • 4.2 Estrategias de ramificación (branching): Git Flow y GitHub Flow.
  • 4.3 Trabajo remoto: push, pull, fetch y remotes.
  • 4.4 Colaboración profesional: pull requests, code reviews y resolución de conflictos.
Producto de aprendizaje Documentación en GitHub evidenciando el historial de versiones, ramas fusionadas y resolución de conflictos.
